# OpenAI-Compatible Responses Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an administrator explicitly choose either Chat Completions or Responses API for the OpenAI Compatible provider while preserving Chat Completions as the default.

**Architecture:** Store one validated protocol setting with values `chat-completions` and `responses`. The generic adapter dispatches request building, endpoint selection, and stream conversion by that setting; the Responses branch reuses Metabase v0.63.2's existing OpenAI Responses request builder and stream transformer. Model discovery remains `GET /models`, protocol selection is never auto-detected, and the thinking/tool-choice retry remains limited to the Chat Completions branch.

**Tech Stack:** Clojure, Metabase settings/API, React, Formik, TypeScript, Jest, Kaocha.

## Global Constraints

- Target `/Users/chengang/Documents/metabase/metabase-v0.63.2` on branch `customization/v0.63.2-migration`.
- Default protocol is `chat-completions` so existing saved configurations do not change behavior.
- Supported protocol values are exactly `chat-completions` and `responses`.
- Do not auto-detect protocols or retry a request through a different protocol.
- Reuse `metabase.metabot.self.openai/openai-request-body` and `openai->aisdk-chunks-xf` for Responses API.
- Do not change conversation-history persistence in this batch.
