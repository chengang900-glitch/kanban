# OpenAI-Compatible Thinking Tool-Choice Retry Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one narrowly scoped compatibility retry for OpenAI-compatible providers that reject required tool choice while thinking mode is active, while preserving authoritative provider errors for every other failure.

**Architecture:** Detect the conflict only from a decoded HTTP 400 response containing both `thinking` and `tool_choice` plus an unsupported marker. Retry the same Chat Completions request once with `tool_choice: "auto"`; do not add thinking flags, alter tool-call IDs, or retry unrelated 400s, 429s, or 5xx responses. Keep v0.63.2's existing AI SDK stream-error framing unchanged and verify it through its existing API regression test.

**Tech Stack:** Clojure, clj-http, Metabase LLM request utilities, JSON, Kaocha test runner.

- Retry at most once and only for HTTP 400 thinking/tool-choice incompatibility.
- Treat `invalid tool_call_id`, HTTP 429, and HTTP 5xx as authoritative provider errors without this compatibility retry.
- Do not implement AI conversation-history changes in this batch.
