# Metabot 执行详情与可靠结束设计

## 目标

同时适用于 AI 助手（`internal`）和 AI 问数（`nlq`），并保持 Metabase v0.63.2 官方交互：执行中显示三个点及简短工具状态，主对话只显示图表链接和一两句关键说明。新增默认折叠的“执行详情”，但不显示模型原始 `reasoning_content` 或完整思维链。

## 界面与数据边界

- 每个助手回合最多显示一个默认折叠的“执行详情”面板。
- 面板只根据已有结构化工具调用生成摘要：数据源、筛选、分组、工具结果、错误。
- 数据源只提取 `source-table`、`source-card`、URI、数据库及明确的数据源字段。
- 筛选和分组只提取相应字段的紧凑摘要；不展示完整查询 JSON、SQL、工具原始输出或 `_reasoning`。
- 工具结果只显示“完成/失败”和经过截断、去控制字符的错误摘要。
- 历史中已存在的 reasoning 块继续保留在数据库，但前端始终隐藏；新回合在流输出和持久化前过滤 reasoning 块。
- 调试模式仍可查看既有工具调用调试信息，但不得恢复原始 reasoning 显示。

## 可靠结束

- Agent 达到最大迭代次数且仍在调用工具时，发送并持久化明确的 `metabot_max_iterations` 错误；前端显示可重试提示，不能静默结束。
- `construct_notebook_query` 对 SQL Server 原生卡片中以 `DECLARE` 开头、又被当作可组合子查询使用的情况提前拒绝，返回可修正的工具错误，不能先声称图表创建成功再由 `/api/dataset` 失败。
- 不修改 DeepSeek/Qwen 的供应商边界：OpenAI-compatible 协议仍识别 `reasoning_content`，只是该内容不进入用户界面和持久化历史。

## 验收标准

1. 执行期间仍显示官方三个点和短工具状态。
2. 正常最终答复格式不改变。
3. 默认折叠面板可展开，且只出现白名单摘要。
4. 当前流和历史 reasoning 均不显示，新 reasoning 不持久化。
5. 最大迭代产生明确错误及重试入口。
6. SQL Server `DECLARE` 原生来源组合查询在工具阶段失败，不生成无效成功图表。
7. 两个源码版本通过相同的前后端针对性测试并构建为 v0.63.2；仅部署 0809 产物。
